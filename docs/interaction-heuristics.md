# Interaction heuristics and stage checks

The main app uses FastAPI/Uvicorn. Detection stays local and reuses YOLO11n pose, stabilized tracked keypoints, optical flow, the configured relative-depth worker and the installed YOLO26s object model. These changes add temporal rules and sampled bag/vehicle context, not another model or training run.

| Observed sequence | Label | Response |
| --- | --- | --- |
| Accepted supported strike passing the saved score and contact gates; slow punches also need exact-contact compatible depth | Possible fight immediately | Save evidence; show live timer; operator review/manual dispatch |
| Continuing supported strikes or sustained grappling reaching the configured escalation time, with fresh compatible depth | Fight detected | Save/update evidence; beep; automatic dispatch after 10 seconds unless acknowledged/cancelled |
| Slow/medium punches: supported body-directed strikes from **both** people across the configured interaction span, with original-contact depth | Fight detected | Same evidence and response workflow; no completed-cycle quota |
| Standing-person reach to another neck/upper chest, then sharp supported pull within 1 second | Possible snatching | Save evidence; operator review/manual dispatch |
| That same actor rapidly moves away with supported leg motion, or measured rapid upper-body departure when legs are cropped, within 5 seconds, and reliable depth supports the original grab | Snatching detected | Update the same incident; beep; existing 10-second dispatch workflow |
| A previously associated rider reaches near the other person's neck, pulls, and moves on the same observed vehicle while the other person reacts toward the rider or falls | Possible rider snatching / review | Opt-in; save evidence; manual dispatch only; does not prove theft |
| Reliable lying posture and low box/torso movement continue for the saved person-down duration | Person down | Save evidence; local review chime; operator review/manual dispatch |
| A stationary bag was previously attended, then has no detected nearby person for the saved duration | Unattended item / review | Opt-in; save evidence and show countdown; local review chime; manual dispatch only |

Missing, uncertain, stale or separated depth cannot produce either stronger label. At least two distinct fresh compatible depth results are required for a fight; they do not need to span a second independent duration. The legacy `responsive` mode is labelled Review only and never confirms a fight. The depth-confirmed mode remains the new-camera UI default. Previously saved incidents are not reclassified.

Fight contact uses confident shoulder/hip and face regions, not the full person box, which can include empty space around extended arms. A bounded torso-length allowance preserves body thickness in side views. A valid limb reach does not require 5% overlap between person boxes; when overlap is below that level, even the review warning requires fresh compatible depth.

Accepted supported strikes start **Possible fight** immediately. `fight_confirmation_seconds` (default 3 seconds, editable from 0.5–10) controls the source-time span from the accepted strike onset to the latest supported observation. The displayed timer freezes during short withdrawals and resumes if support returns within 1.5 seconds; silence cannot confirm a fight. Reaching the time alone is insufficient: a continuing exchange or sustained grappling and two fresh compatible depth samples are still required. `hold_seconds` (default 0.7 seconds) applies to the provisional review window for generic sustained grappling, not the onset of an explicit strike. Grappling integrates actual valid intervals; pauses add no grappling time.

Longer pauses reset motion and depth evidence. If the same reliable pair stays nearby, resuming within the 12-second episode retention reuses the incident ID and handling flags while collecting fresh evidence. It does not create a blind interval or duplicate dispatch. Tracking loss, camera motion, missing poses and depth separation still invalidate evidence. Fresh relative-depth separation vetoes review alerts too. A higher score threshold reduces sensitivity; it is not a probability. Missing depth may allow a review warning for overlapping people, but never confirmation or automatic dispatch.

The slower bilateral path is separate from fast strikes. Each wrist needs measured image motion, a torso-relative approach/extension and a contact with the body, head or a bent raised guard. Body approaches need successive supported observations; a tight, directed guard contact can occupy one sampled frame. Torso padding does not extend slow hand contact below the hips. The contact frame requests bounded priority depth, and that exact original-frame result must be compatible before the strike is accepted. While waiting, the UI says **Checking interaction**, not Possible fight. Supported accepted contacts from both people can qualify before full withdrawals complete; there is no hidden three-cycle quota. Simultaneous two-arm contact alone is not a continuing exchange. An approach without a directed strike starts collection but cannot create a warning. Slow activity does not inflate fast-strike or grappling counters. A depth result arriving after withdrawal can credit its original strike once within the 1.5-second motion grace, using contact time rather than arrival time. After an accepted onset, supported striking with briefly uncertain contact depth preserves continuity but freezes the displayed timer; it cannot start or confirm a fight. A brief uncertain depth result pauses confirmation; uncertainty beyond the 2.5-second freshness bound, unavailable depth or separation invalidates evidence. Confirmation always needs current compatible depth. A bounded near-contact allowance covers staged punches and filter lag without expanding the fast-strike rule. Similar depth alone or unilateral slow motion cannot confirm through this path.

“Same depth” means compatible **relative** depth estimates from the original frames, with uncertainty checks. It does not mean equal numbers or a measured distance in metres, and does not prove an assault. The current compatible bound is normalized depth gap plus the larger interior torso-sample spread at most 0.12, with each spread at most 0.04; a gap at least `max(0.18, 3 × summed spread)` is separated, with intermediate/poor-quality results uncertain. Slow strikes additionally compare the particular attacking wrist with the reached torso, head or guard joint in the original frame. Wrist patches use local spread; distal forearm samples reject abrupt foreground/background crossings without treating a smooth arm-depth gradient as noise. Directed compatibility requires gap plus local spread ≤0.05 and spread ≤0.035. A torso gap over 0.30 vetoes every directed comparison. Different torso planes alone cannot validate or invalidate a reaching arm; its own contacted surface must match. This exception applies only to the identified slow strike. Ordinary fast strikes and grappling retain their original torso-depth gate; another arm’s matching surface cannot qualify them. Snatching retains its separate original torso/grab checks. These are internal limits, not camera-editor settings.

## Editable camera settings

Select a camera, expand **Camera controls**, then **Edit detection settings**. Saving restarts a running/recovering camera with the new settings; manually stopped cameras stay stopped. The camera ID, source, location, saved incidents and enabled state are retained. The same controls and validation apply when adding a camera. A no-op save does not restart it.

| Parameter | New-camera UI default / allowed values | Effect of changing it |
| --- | --- | --- |
| Compute device | Automatic; CPU / MPS / CUDA | Auto chooses available CUDA, then Apple MPS, then CPU for pose. Explicit devices must exist. ZipDepth and weapons remain CPU workers; changing this does not move them to the GPU. Legacy MiDaS/DPT depth uses the chosen device. |
| Fight detection | Depth-confirmed / Review only | Depth-confirmed allows strong labels after all gates pass. Review only can save possible fights but never confirms a fight. It does not switch off other incident types. |
| Relative depth | ZipDepth; Off / MiDaS Small / DPT Hybrid / DPT Large | Selects the depth worker. Off prevents confirmed fights and confirmed snatching. Larger alternatives need their model assets and more compute; switching models is not a guarantee of better detection. |
| Depth updates / second | 1; 0.1–2, at least 0.5 for Depth-confirmed | Higher gives more frequent evidence at more compute cost; lower delays confirmation and can miss brief contact. New interactions can request bounded priority samples between regular updates. |
| Fight score threshold | 0.60; 0.40–0.95 | Lower accepts weaker motion/interaction scores, increasing sensitivity and false-alarm risk. Higher rejects more movements. Applies to fast and slow fight paths, not weapon confidence, posture or snatching. It never bypasses contact, reliable poses or required depth. |
| Sustained interaction observation | 0.7 seconds; 0.3–5 | Sets the provisional review window for close-contact grappling. Explicit supported strikes start Possible fight immediately after their contact checks pass. Independent of escalation timing. |
| Fight escalation time | 3 seconds; 0.5–10 | Sets the supported interaction span before confirmation. Lower shortens the time, but continuing motion and two fresh compatible depth samples remain mandatory; higher waits longer. |
| Person-down observation time | 3 seconds; 1–60 (`person_down_seconds`) | Required source-time duration of supported lying posture and low movement. Does not diagnose injury or change fall onset. |
| Analysis frames / second | 8; integer 2–30 | Higher samples pose/motion more densely but uses more compute; lower can miss brief reaches or produce coarse trajectories. This is a target, not guaranteed throughput. Preview separately targets up to 8 FPS. |
| Knife & gun detection | On / Off | Toggles the specialist independently of fight/bag rules. Its fixed confidence requirement remains **strictly above 90%**. |
| Unattended-item checks | Off / On (`unattended_objects`) | Enables same-frame person/bag sampling with YOLO26s. Can run with weapons off and without specialist weights. |
| Unattended-item wait | 60 seconds; 10–3600 (`unattended_seconds`) | Continuous observed absence after prior attendance; not time since camera connection or browser refresh. |
| Rider snatching review | Off / On (`snatching_vehicles`, default false) | Enables vehicle context and the separate review-only rider sequence; can run with weapons off. Existing cameras remain off until enabled. |
| Object updates / second | 1; 0.2–2 | Shared object-worker cadence for enabled weapon/bag/rider checks, independently of pose FPS. Lower rates can miss objects or attendance. |
| Eco mode | Off / On | On reduces quiet-scene pose sampling to about 2 FPS, depth to at most 0.1 updates/second and weapons to at most 0.5. Motion or pending interactions restores active rates. Saves compute but can miss subtle activity before wake-up; leave off while calibrating slow punches. |

The selected inspector, camera cards and full feed show live backend timer values, including paused, waiting-for-depth and waiting-for-strikes reasons. They never advance from the browser clock or a saved incident; stopped/stale cameras hide the timer. Camera controls separately displays worker readiness/freshness, tracked-pair compatibility and score blockers. Technical details show the matching-depth span as telemetry, not another countdown. A ready model does not prove contact, and relative depth is not distance in metres. The API uses `PATCH /api/cameras/{id}/settings`; only the tuning fields above are accepted, with creation limits and merged cross-field validation before any interruption.

The standing snatching rule estimates movement; it does not detect a necklace or prove theft. Both shoulders and one visible hip can support a partial side view. Reach and pull need articulated, torso-relative wrist motion, so translating a rigid body past another person does not qualify. Rapid departure requires distance gained through the same actor's own movement and supported leg motion. Signed per-step distance changes allow escape across the camera view without crediting victim-only movement or ignoring inward reversals. If both ankles are cropped, a separate route needs at least five reliable torso observations, substantial outward displacement and strong torso image motion. The departure history expands to at most two seconds at 2 FPS rather than lowering the observation count. Track/scale jumps, victim-only or unrelated-person running, and disappearance cannot complete the earlier actor's sequence. Grab depth is checked at the original contact; known incompatible depth suppresses provisional snatching too. Small subjects, occlusion and perspective remain limitations.

### Rider snatching review

Enable **Rider snatching review** in Add camera or Edit detection settings. The setting accepts only booleans in the API and only camera/recorded-video inputs (`mode=live`), not synthetic pipeline tests. It defaults Off for new and previously saved cameras. YOLO26s supplies vehicle context without needing weapon weights. Changing the setting does not reclassify old incidents; reanalyse a recording to apply it.

This separate path requires a previously observed rider/motorcycle association, articulated wrist reach near the other person's neck and a supported pull within one second. Confident raw wrist geometry permits a bounded horizontal hand allowance of 0.18 target scale; the neck region is not extended vertically. Stabilized wrist motion still has to support reach and withdrawal. Within three seconds of the pull, the same rider and original motorcycle must each move at least 0.20 actor scale with supported trajectory, and the motorcycle must be observed again after the pull. Rider movement needs at least four observations spanning 0.4 seconds, normalized speed at least 0.20 and measured image motion at least 0.12 in three observations.

The target must move at least 0.25 target scale with normalized speed at least 0.4, across at least four observations spanning 0.4 seconds with image motion at least 0.12 in three. That motion must either include at least 0.20 scale toward the rider's original position or a supported falling posture. Fall posture alone cannot bypass the motion/observation checks. YOLO26s motorcycle and matched person context must reach 0.4 confidence; bicycle support is not included. These internal gates are movement heuristics, not measured theft probabilities.

Vehicle presence, ordinary travel or a nearby hand alone cannot alert. A phone exchange with coincident movement can still resemble this sequence, so manual review is necessary. Pending evidence retains the original vehicle rather than attaching to a new motorcycle-like box after the person falls. Tracking gaps, discontinuities and camera motion invalidate continuity. A falling target need not remain standing, but unsupported identity recovery cannot invent a reaction.

The result is **review-only**: it saves evidence and can use the existing optional Gemini reporting workflow, but cannot emit `snatching_detected` or start an automatic phone countdown. The existing standing-person depth-confirmed rule is unchanged. The inspector exposes current rider-check status rather than inferring progress from a saved incident.

Use 8 analysis frames/second and 1 object update/second as the starting replay settings. Sampling rate affects which vehicle observations are available: a weak or ambiguous new vehicle sample interrupts the pending sequence, while a slow rate may miss its movement. More object updates do not guarantee better detection. Validate each camera with several positive and ordinary-interaction clips; the checked example is not an accuracy benchmark. At 2 analysis FPS, movement histories retain four observations for up to two seconds, but a brief reach or pull can still fall between samples.

## Person-down and unattended-item checks

Person-down checks require reliable shoulders and at least one visible hip. A broad lying body can qualify with cropped lower limbs; compact or diagonal postures additionally need a visible straight leg aligned with the torso. Seated, bent-over, moving and unreliable poses are rejected. The saved `person_down_seconds` controls low-movement duration; camera motion, missing observations, track jumps and frame gaps reset continuity and prior fight context. The result is a reviewable posture, not a medical diagnosis.

Unattended-item checks use YOLO26s COCO classes **person/backpack/handbag/suitcase (0/24/26/28)** from the same sampled frame. General inference uses a 0.2 cutoff; bags must independently reach 0.5. Weak nearby person detections interrupt an absence claim; a person must reach 0.4 to establish attendance. No current pose box is substituted for the sampled frame's people.

A bag must be stable alongside exactly one nearby person for **at least two source seconds and three observations** before it can arm. Only then does continuous absence of any nearby detected person start the configurable countdown. Never-attended bags, other static fixtures, carried/moving bags, ambiguous matches and brief occlusion cannot complete it. Missing/error/stale samples, backwards time, shape changes, excessive sample gaps and camera movement invalidate evidence. Tracks are capped at **24 bags**; one stationary episode emits one incident with its prior attendance, object box and duration metadata.

The inspector shows source-sample countdowns, not a browser timer. Completed events use the existing incident clips, review and optional Gemini report workflow. Similar proximity does not prove ownership or placement, and object appearance cannot establish explosive contents. These are **unattended-item review alerts**, not bomb detection. After **Enable alarm sound**, recent unreviewed physical-camera unattended-item, person-down and possible-fall incidents can produce one local chime. They do not add a phone countdown: `AUTO_EVENTS` remains `fight`, `knife_detected`, `snatching_detected`; manual response remains available.

## Processing and continuity

- Analysis defaults to 8 FPS and preview polling targets up to 8 FPS. Live capture keeps the latest frame rather than queuing old footage. Recorded analysis keeps one frame until processed, caps height at 480 pixels, samples at configured analysis FPS and preserves source timestamps. It waits for selected original-frame depth and, when unattended checks are enabled, sampled object results through model warmup. This source-time backpressure prevents fast file decoding from skipping the absence interval; analysis can take longer than playback. Eco skipping is disabled for recordings. Live object work remains bounded and asynchronous; source-frame sequence/time/shape and cached camera motion must match before attendance counts.
- Detailed contact checks skip distant pairs. Fight and snatching rules share stabilized poses and image-motion evidence. Histories are short and discarded on frame/identity discontinuities or camera movement.
- A newly observed neck reach or fight candidate requests its exact frame for depth immediately, bypassing the regular interval within a bounded priority rate. The worker retains only one pending request. Depth joins require the original sequence, source time and image shape; no stale map is attached to a newer pose.
- A pending grab keeps Eco at active sampling. For live cameras, quiet mode still uses periodic checks; very brief actions can be missed before the motion wake-up or when effective analysis FPS is low.
- `stage_ms` reports pose, motion/stabilization, rules, and rendering/encoding time separately. Depth and object inference expose their own latency. These measurements help tune the camera without guessing which model is slow.
- Provisional and stronger labels share an incident ID for the same episode. The first timestamp, existing review and original evidence are retained. Escalation adds stage metadata and a fuller clip. Earlier manual dispatch/cancellation is preserved, so upgrading an incident does not create another automatic call.
- Operator handling still releases the inspector after the existing 30-second period. A later separate episode gets a new incident; continuous visibility is not a reason to dial repeatedly.

## Stage verification

Suggested starting settings for the existing laptop/stage setup: Automatic compute, 8 analysis FPS, Depth-confirmed mode, ZipDepth at 1 update/second, score threshold 0.55, sustained observation 0.7 seconds, escalation time 3 seconds (or 1 second for faster stage review), Eco off, and weapon sampling at 1 update/second when enabled. This is a calibration starting point, not a measured optimum. Defaults/saved values are not automatically changed. Lowering the score cannot replace missing poses, actual motion support or depth.

The escalation control is a supported source-time clock, not elapsed browser time after any saved warning. Its visible progress can pause, reset or wait at the target for depth/continuing strikes. Exact-contact priority depth may arrive between regular samples, but worker latency and missing evidence can still delay confirmation. No separate full-duration depth window or completed-punch quota is added after the clock. Defaults and existing camera settings are not silently changed.

Use a fixed camera with both participants upright, clearly visible and large enough for reliable shoulders, hips, wrists and legs. Start with a few seconds of normal movement so tracking can settle. Compare safe staged movements with ordinary interactions in the same camera view.

Record separate examples of strikes, grappling, neck reach/pull and same-person escape, including partial side views and 2 FPS sampling. For rider review, compare a supported reach/pull/departure/reaction sequence with normal roadside conversation, phone gestures, vehicle pass-by, target-only motion and ambiguous motorcycle detections. Include handshake/hug/collar adjustment, rigid-body translation, walking together, unrelated/victim-only running, track jumps, camera shake and occlusion. For person-down, include lying/diagonal poses and seated/bent-over/moving negatives. For bags, compare attended-then-left, never-attended fixtures, carried/moving bags, nearby passersby and ambiguous/occluded detections. Examine saved clips and blockers; a smooth preview alone does not establish valid depth or attendance.

For a rehearsal without contacting anyone, use an isolated test centre or explicitly turn calling/messaging off in Centre settings. The automated development tests use synthetic data and no provider calls. Production calling settings are preserved by this update.

Automated rule/engine tests verify timing, depth/frame provenance, negative cases, bounded state, identity continuity, incident upgrades and response deduplication. They do not measure CCTV precision/recall or prove four-camera operation on 4 GB. Supplied stage clips are local calibration examples; independent sessions are still needed for generalization and false alarms per camera-hour. Model retraining and learning from reviewed clips remain separate work.
