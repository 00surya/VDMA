Try a decision ↗
Two related ideas. Two different models. This page draws on the English auto-generated subtitles of CampusX’s Jev by TypeSafe AI | What is a System-1 Decision Model (24 September 2026). Jev is the video’s subject; GLiNER2.5-Decide is what this app actually runs. At 55:20, the presenter explicitly says Jev’s internals have not been published and the proposed architecture is speculative. The notes below preserve that distinction.

The path your request takes

01 / INPUT

State + schema

Your state is the text. The question becomes the classification prompt; your options become the candidate labels.

question → prompt
02 / ENCODE

Shared context

GLiNER packages text and schema tokens together. Its DeBERTa-v3-large encoder computes contextual representations in one forward pass.

text + labels → vectors
03 / SCORE

Classification head

The classifier scores each candidate’s representation. Softmax turns those logits into a distribution over your supplied choices.

softmax(logits)
04 / RETURN

A structured result

The app sorts every option by score, highlights the largest, and returns the distribution with measured model-call time.

argmax → top choice

The exact checkpoint matters

The publisher calls this the 340M English Decide model. Its pinned configuration declares architecture: span and model_name: microsoft/deberta-v3-large. AutoExtractor therefore loads a SpanExtractor. This page describes its classification route, not the boundary extraction architecture used by other GLiNER2.5 checkpoints.

Inspect the pinned configuration ↗

Where those bars come from

The local GLiNER2 2.0.0 runtime applies softmax across label logits. The app requests all labels with a zero selection threshold and explicitly retains softmax. This exposes the full single-choice distribution in one call; it does not invent scores for the losing options.

The percentages sum to approximately 100% before rounding. Changing your choices can change every score. These probabilities have not been calibrated on your tasks.

SUBTITLE-BASED NOTES
04:06 — THE DECISION INTERFACE ↗

Define the answer space first.

The presenter introduces a classifier that accepts context, a question and choices. That interface inspired the three input cards in this playground. The result is a selection from the options, rather than a newly written explanation.

12:35 — PARALLEL DECISIONS ↗

Many decisions can share context.

The video describes Jev answering several questions together. GLiNER also supports multiple classification tasks in one schema. This playground exposes one editable question per run to keep the state-to-answer flow visible.

16:02 — CALIBRATION ↗

Confidence needs evidence.

The video compares reported confidence with observed accuracy. On a calibrated task, predictions near 80% should be correct about 80% of the time across many comparable cases. A softmax value alone does not establish that relationship.

The architecture hypothesis in the video

JEV · NOT VERIFIED INTERNALS
PROPOSED BACKBONE

A pretrained transformer

The presenter conjectures a pretrained decoder backbone. The exact model, parameter count and attention design are not established by the video.

PROPOSED READ STEP

Context processing

The hypothesis retains a stage that processes the context and question, while removing the usual repeated next-token generation loop.

PROPOSED OUTPUT

An answer head

An option-scoring head replaces vocabulary-wide token generation in the presenter’s sketch. The result is a constrained choice.

DISCUSSED TRAINING

Calibrated decisions

The video discusses synthetic training and RLCD for confidence calibration. This is not a claim about the GLiNER checkpoint installed here.

Read the sketch as a teaching aid

The answer-head discussion at 70:15 explains how avoiding token-by-token prose could reduce latency. At 76:26, the presenter proposes separate question paths sharing context. Neither sketch verifies Jev’s implementation.

What transfers to this playground

The useful interface pattern is concrete: describe a state, constrain the choices, score them, then let application logic decide what to do. GLiNER implements that pattern with its documented encoder and classifier. Jev’s reported latency, training method and calibration do not transfer to this local model.

Use the small model between larger steps

Near 86:03, the presenter describes larger models planning while decision models handle intermediate choices. For VDMA, a future integration could turn verified observations into text, classify a bounded review question, then apply explicit application rules.

Start with representative examples

Include ordinary interactions, ambiguous descriptions and an “insufficient evidence” option. Compare predictions with independently reviewed labels before choosing thresholds. This standalone lab supports those experiments; it does not change VDMA’s detection or response logic.
